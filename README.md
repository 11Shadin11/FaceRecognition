# Локальное распознавание лиц

Учебное настольное приложение: показывает камеру, распознаёт зарегистрированных
людей и добавляет образцы из камеры или видео. Использует готовую модель
`face_recognition` / dlib. Добавление образцов не обучает нейросеть заново.

Интерфейс использует тёмную палитру с цветными акцентами. Слева — камера,
рамки с именами и крупный результат; справа — счётчики базы и добавление
образцов. Индикатор сверху показывает состояние источника. Цвет результата
сопровождается текстом, поэтому совпадение понятно и без различения цветов.
Палитра и стили собраны в `face_app/theme.py`. Новых зависимостей нет:
оформление статично, виджеты меняются только при изменении их состояния,
превью и модель продолжают работать независимо друг от друга.

## Запуск

Нужны Python 3.9–3.12 с Tkinter / Tk 8.6 или новее, C++ compiler и CMake 3.x для сборки dlib.
На macOS предпочтителен отдельный Python с поддержкой Tk, а не системный Python.
На Linux Tkinter может потребовать установки пакета `python3-tk`.

На этом Mac подготовлено отдельное окружение `.venv-tk` с Python 3.12 и Tk 9.
Можно открыть `FaceRecognition.app` двойным кликом в Finder. Терминал не нужен.
Это небольшой локальный запускатель: оставьте его в папке проекта рядом с
`face_app/`, `faces_recognition.py` и `.venv-tk`. Python и зависимости не включены
в пакет приложения. При ошибке запуска подробности находятся в
`data/launcher.log`; размер журнала ограничен при следующем запуске.

Запуск из каталога проекта:

```sh
./.venv-tk/bin/python faces_recognition.py
```

Для создания такого окружения на другом Mac:

```sh
brew install python@3.12 python-tk@3.12
$(brew --prefix python@3.12)/bin/python3.12 -m venv .venv-tk
source .venv-tk/bin/activate
python -m pip install --upgrade pip wheel 'setuptools<81' 'cmake>=3.25,<4'
DLIB_PNG_SUPPORT=OFF CMAKE_BUILD_PARALLEL_LEVEL=2 python -m pip install --no-build-isolation -r requirements.txt
```

На macOS 27 текущий Homebrew не распознал версию ОС. Для установки здесь
использованы готовые сборки для macOS 26:
`HOMEBREW_FAKE_MACOS=26 HOMEBREW_NO_AUTO_UPDATE=1 brew install --force-bottle python@3.12 python-tk@3.12`.
Это разовая настройка команды установки; запуск приложения её не требует.
Старое окружение `.venv` с системным Tk 8.5 оставлено, но для GUI не используется.

Общий вариант установки для Python с уже работающим Tk:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip wheel 'setuptools<81' 'cmake>=3.25,<4'
DLIB_PNG_SUPPORT=OFF CMAKE_BUILD_PARALLEL_LEVEL=2 python -m pip install --no-build-isolation -r requirements.txt
python faces_recognition.py
```

Разрешите Python доступ к камере в настройках ОС. Если нужна другая камера:

```sh
python faces_recognition.py --camera 1
```

Номер можно менять в поле «Источник №» при остановленной задаче. Выбор
сохраняется в `data/settings.json`; следующий запуск его использует.
Явный аргумент `--camera` имеет приоритет. Если настройки повреждены,
используется камера №0. Приложение не перебирает камеры автоматически.
При подключённом iPhone камера №0 может оказаться камерой телефона:
на этом Mac встроенная FaceTime проверена под номером 1. Номера могут меняться
после подключения устройств. Если камера несколько секунд выдаёт почти чёрные
кадры, приложение сообщает об источнике и освобождает его; проверьте выбор
камеры, шторку и освещение.

Пути по умолчанию вычисляются относительно проекта, поэтому запуск из другой
рабочей директории поддерживается. Можно задать `--data-dir`, `--legacy-dir`
и `--threshold` (по умолчанию 0.6). Основные настройки находятся в
`face_app/config.py`; порог и критерии качества требуют подбора на своих данных.

## Работа с базой

1. Введите имя человека или выберите существующий профиль.
2. Нажмите «Записать с камеры», «Фото» либо «Видео».
3. В кадре должен находиться только выбранный человек. Кадры без лица,
   с несколькими лицами, слишком маленьким, размытым или плохо освещённым лицом
   не принимаются. Камера собирает образцы 8 секунд после первого кадра.
4. Запустите распознавание. «Остановить» и Escape останавливают текущую задачу.

Кнопка «Фото» импортирует до 100 выбранных JPEG/PNG одного человека.
Проверяются число лиц, размер, резкость и освещение; повторные образцы одного
профиля не дублируются. Исходные файлы сохраняются. Прогресс показывается только
у активной задачи с известной долей завершения; в ожидании и при распознавании
пустой полосы нет.

«Профили и образцы» открывает отдельное окно со списком людей и просмотром
фотографий. Здесь можно переименовать профиль, удалить выбранное фото или весь
профиль после подтверждения. Переименование сохраняет внутренний ID и готовые
описания лиц. Изменения используются при следующем запуске распознавания.
Сначала остановите текущую задачу. Чтение выбранного фото и операции с базой
выполняются в фоне; все фотографии одновременно в память не загружаются.

Во время распознавания на превью появляется рамка с подписью: зелёная с именем
для совпадения, красная «Неизвестный человек», жёлтая для неоднозначного
результата. Координаты берутся из того же вызова модели, что и имя; повторного
поиска лиц для отрисовки нет. Рамки масштабируются вместе с изображением,
учитывая поля по краям, и исчезают при остановке или если результату более
0,5 секунды. Превью продолжает показывать свежие кадры независимо от модели.

Видео обрабатывается последовательно с выборкой по FPS (при отсутствии корректного
FPS используется 30). По умолчанию пределы: первые 5 минут видео, не более 100
принятых или повторяющихся образцов за импорт. При отмене уже принятые образцы
остаются в базе. Превью камеры обновляется отдельно от распознавания; результаты
старше секунды скрываются, чтобы не выдавать старый результат за текущий.

Старая структура `faces/<имя>/*.jpg` или `*.png` импортируется кнопкой
«Старая база». Исходные фото и видео не удаляются.
`encoded_faces.pkl` никогда не открывается: описания создаются из фотографий.
Папки `test`, `tests`, `pig`, скрытые папки, ссылки и неподдерживаемые файлы
исключены. Импорт проверяет каждую фотографию; повторный импорт не дублирует
неизменённые принятые образцы. Имена папок считаются метками: приложение не может
автоматически установить, правильно ли исходный человек был подписан.

Новая база:

```text
data/
  faces.sqlite3                   # профили, хеши, JSON-описания, версия модели
  profiles/<внутренний ID>/*.jpg   # уникальные имена; имя человека не часть пути
```

SQLite обновляется транзакционно, изображения записываются через временный файл
и атомарное переименование. После аварийного завершения между сохранением файла
и фиксацией SQLite возможен неиспользуемый файл; он не попадает в индекс.
Каталоги и файлы создаются с ограниченными правами на Unix. Это не шифрование.
«Копия ZIP» сохраняет снимок SQLite и только связанные с ним фотографии.
Пока идёт копирование, изменения базы заблокированы. Хеш каждого фото
проверяется; ошибка или отмена не оставляет готового неполного архива.
Архив создаётся с правами `0600`, существующая копия не перезаписывается.
Номер камеры в архив не включается: он относится к устройствам этого компьютера.
Альтернативный способ — закрыть приложение и скопировать весь каталог `data/`.
Для восстановления собственной ZIP-копии закройте приложение, распакуйте её в
новую папку и запустите с `--data-dir /путь/к/распакованной/data`.
Сначала проверьте профили и фотографии; текущую базу можно оставить рядом.

Удаление сначала перемещает фото во временный закрытый каталог, затем меняет
SQLite. При штатной ошибке транзакции фото возвращаются. После аварии ОС
может остаться `.deleting-*` внутри `data/`; такие каталоги не очищаются
автоматически, поскольку в них могут быть фотографии для восстановления.
Фотографии, SQLite и старые pickle-файлы исключены из Git.

## Структура кода

| Модуль | Ответственность |
| --- | --- |
| `face_app/main.py` | Аргументы запуска и создание приложения |
| `face_app/config.py` | Настройки и пути |
| `face_app/models.py` | Объекты данных, валидация описаний и выбор совпадения |
| `face_app/storage.py` | SQLite, безопасные пути, сохранение фото, перечисление старых данных |
| `face_app/recognition.py` | Цвет, масштабирование, качество кадра, dlib и векторное сравнение |
| `face_app/engine_process.py` | Постоянный процесс модели, запросы, таймауты и прерывание вычислений |
| `face_app/capture.py` | Процесс захвата, ограниченные очереди, освобождение источника |
| `face_app/tasks.py` | Одна фоновая задача, отмена, передача состояния в интерфейс |
| `face_app/service.py` | Сценарии импорта, сбора образцов и распознавания |
| `face_app/ui.py` | Только Tk-интерфейс и обработка опубликованного состояния |
| `face_app/theme.py` | Палитра, типографика и общие стили виджетов |
| `face_app/overlays.py` | Рамки и подписи на Canvas, масштабирование и скрытие устаревших результатов |
| `face_app/preview.py` | Быстрое преобразование BGR в RGB для превью и масштабирование |
| `face_app/profiles_ui.py` | Просмотр образцов и управление профилями через фоновые операции |
| `face_app/preferences.py` | Проверка и атомарное сохранение выбора камеры |
| `face_app/backup.py` | Согласованная резервная копия базы и фотографий |
| `face_app/evaluation.py` | Проверка на отдельной размеченной выборке без изменения базы |
| `tools/check_*.py` | Проверки интерфейса, жизненного цикла захвата и ресурсов без камеры |

Старые файлы `faces_recognition.py`, `dialog_window_module.py`,
`generate_data_set.py` оставлены как точки запуска. Импорт модулей не создаёт
окна и не включает камеру. Демонстрации `face_landmarks.py` и `pig_nose.py`
запускаются отдельно, освобождают камеру и закрывают окна через `finally`.
Для фильтра нужен отсутствующий в репозитории `faces/pig/pig-nose.png`.

Все виджеты обновляет основной поток через `after()`. Одно фоновое задание
координирует импорт, кеш и сохранение данных. Модель и обработка изображений
находятся в отдельном постоянном процессе: нативные вызовы dlib не удерживают
GIL интерфейса. Модель переиспользуется между задачами. Для каждого источника
создаётся отдельный процесс захвата, который освобождается при остановке.
У живого видео сохраняется только свежий кадр; у импортируемого файла очередь
ограничена двумя выбранными кадрами и продюсер ждёт потребителя.

Отмена или таймаут прерывают зависший процесс вычислений; следующая задача
загрузит модель заново. Драйвер камеры останавливается независимо от модели.
Закрытие окна не ожидает освобождения ресурсов в обработчике Tk: интерфейс
проверяет завершение через `after()`. Внутренние сообщения между собственными
процессами не используются для чтения внешних сериализованных файлов.

Кеш описаний проверяет хеш изображения и версию модели. Новые или изменённые
образцы пересчитываются, остальные используются повторно. Сравнение вычисляет
расстояния один раз; лучший образец выбирается отдельно для каждого человека.
Близкие результаты разных людей дают «Неоднозначное совпадение».

## Проверки

```sh
python -m unittest discover -s tests -v
python -m compileall -q face_app tests *.py
```

Проверки настоящего Tk и OpenCV без физической камеры:

```sh
./.venv-tk/bin/python -B tools/check_interface.py
./.venv-tk/bin/python -B tools/check_capture_lifecycle.py --cycles 100
./.venv-tk/bin/python -B tools/check_responsiveness.py --seconds 1200 --output /tmp/face-resources.json
```

Последняя команда повторяет настоящую модель и отрисовку превью на искусственном
кадре. Можно добавить `--image /путь/к/фото.jpg` для нагрузки с лицом: фото только
читается, база создаётся во временной папке, камера не включается. Отчёт содержит
интервалы таймера Tk, время модели и замеры суммарной памяти/CPU приложения и
процесса модели (сумма RSS; общие страницы памяти могут учитываться несколько раз).
Это проверка ресурсов, а не точности узнавания или драйвера
камеры; интервал таймера также не является FPS камеры.

Основные тесты не включают камеру и не требуют модели. При установленных
зависимостях отдельно проверяются загрузка настоящей модели, кадр без лиц и
вычисление описания заданной искусственной области; это не измерение точности.
Проверки обработки изображений дополнительно используют NumPy, OpenCV и Pillow. Тесты покрывают
выбор личности, безопасное хранение, повреждённый кеш, повторный импорт,
инвалидацию описаний, отмену и освобождение источника, включая зависший процесс.

Для CMake, установленного через pip, используется `--no-build-isolation`:
изолированная сборка dlib может не найти Python-модуль обёртки CMake.
`DLIB_PNG_SUPPORT=OFF` обходит ошибку встроенной libpng dlib на новых macOS SDK
(`fp.h` отсутствует). PNG-файлы приложения по-прежнему читает Pillow; dlib
получает готовые RGB-массивы. `CMAKE_BUILD_PARALLEL_LEVEL=2` ограничивает нагрузку
при сборке. Эти настройки не изменяют библиотеки системы.

Для ручной проверки: отсутствие камеры, отказ в разрешении, отключение камеры
во время работы, пустая база, отмена импорта и закрытие окна во время обработки.
Реальные FPS и качество зависят от компьютера, камеры и данных; нужны отдельные
измерения. Проценты «уверенности» и прежняя неверная функция «точности» удалены.
Для оценки качества нужна отдельная размеченная проверочная выборка, которая
не участвует в регистрации людей.
Сценарий подготовки такой выборки и команду оценки см. в `docs/checks.md`.

## Ограничения

Это экспериментальное распознавание, не механизм безопасного входа: защиты от
фотографий, повторного предъявления и подмены камеры здесь нет. Интеграция со
вторым проектом пока не реализуется.

Модель `shape_predictor_68_face_landmarks.dat` нужна только дополнительным демо.
Если это стандартная модель dlib на iBUG 300-W, проверьте условия перед
коммерческим использованием: https://dlib.net/face_landmark_detection.py.html.
